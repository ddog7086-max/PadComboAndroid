# 轉珠路徑覆蓋層渲染規格（直線合併 · 井字 / 王字分層）

> 適用工程：`PadComboAndroid` / `overlay/RouteBoardView.kt`
> 原則：所有平滑、錯位、分層都屬於**視覺渲染層**；搜尋器輸出的原始 `Cell` 軌跡、步數、起終點與交換語意**不變**。

## 0. 分層邊界（先講清楚什麼不能動）

| 層 | 職責 | 不可越界 |
|---|---|---|
| 搜尋層（`BeamSearchSolver` / `BoardEngine`） | 產生原始格點序列 `route: List<Cell>`、Combo、消除數 | 不因畫面好看而改動路徑、強行避重訪、刪格或換序 |
| 辨識層（`BoardRecognizer` / `BoardRectHelper`） | 盤面矩形、珠心座標 | 不參與折點合併 |
| 渲染層（`RouteBoardView`） | 格點→像素、偏移車道、同向合併、圓角、起點圓點、終點箭頭、clip | 只產生畫圖用的點列；不得回寫 `route` |

合併後的折點列是**渲染副本**；步數、重訪統計、車道編號一律先在原始序列上算完，再做折點壓縮。

## 1. 直線段合併與轉折點規則

### 1.1 輸入與方向向量
- 原始序列 `route = [c₀, c₁, …, cₙ₋₁]`，每格 `Cell(row, col)`。
- 基礎像素點 `base[i] = rect.center(colᵢ, rowᵢ)`。
- 步方向 `dᵢ = (colᵢ₊₁ − colᵢ, rowᵢ₊₁ − rowᵢ)`，轉珠格網只會是四個單位方向：
  `(-1,0) 左 / (1,0) 右 / (0,-1) 上 / (0,1) 下`。

### 1.2 保留折點的判定（索引 i）
`keep[i] = true` 若任一成立：
1. `i = 0`（起點）或 `i = n−1`（終點）；
2. **轉折**：`dᵢ₋₁ ≠ dᵢ`；
3. **即時掉頭**：`dᵢ₋₁ = −dᵢ`（視為轉折，不可併入直線）；
4. **車道邊界**：邊 `(cᵢ₋₁,cᵢ)` 或 `(cᵢ,cᵢ₊₁)` 在無向邊統計中被重訪 ≥ 2 次；
5. **重訪格**：`cᵢ` 曾在更早出現過（作為車道切換點保留）。

其餘落在「連續同向段」中間的格點全數刪除，一段同向只留首、尾兩點，畫成單一直線。

### 1.3 合併前後不可變的東西
- 起點格、終點格不變；最後一段方向仍以原始邊計算箭頭朝向。
- 重訪判定 `edgeCount` 用**原始邊序列**算，不能先壓縮再數重邊，否則井字 / 王字會分不出層。
- `route.size`（步數）、Combo、消除結果完全不參與合併。

### 1.4 圓角 / 平滑
- 只在**保留的轉折點**上套用圓角；同向直線段不做弧度。
- 圓角半徑 `r = min(0.16·cell, l₁/2, l₂/2)`，`l₁/l₂` 為相鄰兩保留邊的像素長度；段長過短就退化成直線接點。
- 端點、圓角控制點、箭頭頂點全部過 `clampPointToBoard`。
- 不做大弧度貝塞爾亂扭；保持正交折線 + 統一圓角。

### 1.5 避免過度簡化的檢查
- 只合併**完全相同**的單位方向；格網沒有斜步，不要用「角度近似」合併。
- 掉頭、重訪邊界、重訪格一律保留，否則車道跳動會被吃掉。
- 壓縮後若出現重疊相鄰點（相同像素），`buildRoundedPath` 以 `lineTo` 兜底，不生成零長度控制點。

## 2. 井字形 / 王字形交錯重疊繪製方案

### 2.1 既有渲染架構（沿用，不推翻）
- 無向邊 `edgeKey(a,b)`：點座標排序後組字串，去方向。
- `edgeCount`：邊被經過次數；單次邊偏移 0，筆直穿珠心。
- 重訪邊沿**固定朝向的法向**分配平行車道；法向不隨行走方向翻轉（避免去回程擠同側）。
- 頂點偏移**分軸累積**：水平相鄰段只貢獻 Y、垂直相鄰段只貢獻 X，不做向量平均，防止水平線被拉斜。
- 現行車道：`N=2 → ±12dp`；`N=3 → −14dp, 0, +14dp`。

### 2.2 「井」字形情境
**幾何特徵**：局部橫、豎兩向都有重訪與交叉；格線感強；同一段邊去回程各走一次。

**偏移策略**
- 水平重訪邊：車道槽位沿垂直法向（Y）錯開。
- 垂直重訪邊：車道槽位沿水平法向（X）錯開。
- 交叉點兩向偏移互不干涉（分軸累積）；不在交叉處繞線、不彎道迴避對方。
- 槽位以中心線對稱：`position = (lane − (N−1)/2) · spacing`。

**分層畫線順序（由下到上）**
1. 單次中心線（偏移 0）先畫；
2. 重訪車道由外槽往內槽畫；
3. 起點圓點、終點箭頭最後畫。
後畫的內槽壓在外槽之上，交叉處先後可讀。

### 2.3 「王」字形情境
**幾何特徵**：同一橫帶內有數條上下排列的水平折返（上層 / 下層來回），穿插少量直向貫穿；需要區分各水平層的先後次序。

**偵測（啟發式，渲染層內做）**
- 把連續水平邊歸入所屬 `row` 的水平帶；統計每個水平帶被經過的水平通過次數 `bandN`。
- 同帶內第幾次通過 → `visitRank`；直向貫穿段另外按垂直通過次序給槽位。

**偏移策略**
- 水平層車道沿垂直法向開槽，槽距以**格寬比例**為準（建議 `0.10–0.12 cell`），不要用固定 dp，避免不同螢幕尺寸下擠在一起或漂出珠心。
- 層內槽位：`(visitRank − (bandN−1)/2) · bandSpacing`，上下對稱。
- 直向穿插段沿水平法向開槽；不與水平層搶同一個法向。
- 單帶車道上限 `N ≤ 3`；超過 3 次的通過，不再加實體槽位，改以畫圖次序（後走壓上）表達，避免偏移溢出。

**先後次序表達（不違反「不畫中段序號」的既有決策）**
- 靠槽位遠近 + 畫圖次序區分，不加逐格步號。
- 可選：後走內槽維持純白；外槽白色透明度略降（建議下限 0.85），但**不回退到雙層灰管道 / 複線**。

### 2.4 偏移預算（兩種字形共用）
- 任一車道離中心線的最大總偏移 ≤ `0.28 cell`；超出就壓縮槽距或降層級，不把線推出珠子。
- 邊界夾取：頂點 / 控制點 / 箭頭三類點都過 `clampPointToBoard`；`clipRect` 硬裁剪兜底（左右內縮 0.18cell、底 `bottom − 0.45cell`）。

### 2.5 交叉與終點保護
- 終點箭頭所在的最後一段，終點優先回到原始珠心法向附近；車道偏移不得把箭頭推離該珠。
- 箭頭尺寸 `0.16 cell`，頂點同樣夾回盤面內框；箭頭最後畫，不被車道線蓋住。

## 3. 邊界與實作注意事項（手機 Canvas / Path）

### 3.1 幾何與壓縮
- **過度簡化**：只認同單位方向；角度近似、掉頭、重訪邊界都不能併。壓縮後必須驗證起終點座標不變。
- **車道統計時機**：先對原始序列算 `edgeCount` / 重訪格，再做折點合併；合併結果不回餵統計。
- **短段圓角**：相鄰保留邊長度不足半徑時，半徑自動取 `min(…, l/2)`；零長度點用 `lineTo`。
- **座標型別**：所有頂點 / 控制點傳給 `Path` 前轉 `Float`，避免 Double 混繪製。

### 3.2 偏移與邊界
- **偏移溢出**：槽距用格寬比例封頂；禁止單向大偏移把整條線推下盤面（舊 U 型彎掉出底邊的教訓）。
- **分軸累積**：X 偏移只來自垂直鄰邊、Y 偏移只來自水平鄰邊；混用向量平均是斜線主因。
- **法向固定**：法向朝向與行走方向解耦；豎直邊法向朝下時再翻轉，確保去回程同側規則一致。
- **底行保護**：row 4 珠心在 `bottom − 0.5cell`；夾取上限 `bottom − 0.52cell`，`clipRect` 兜底 `bottom − 0.45cell`，不進入下方深啡邊界。

### 3.3 效能與重繪
- 路徑長度約 ≤ 20 格；幾何（基礎點、邊統計、車道、合併折點）在 `show()` 時算一次，`onDraw` 只做取物件畫圖。
- `Paint` / `Path` 盡量復用；`onDraw` 內不重新分配邊統計表。
- 相同路徑連續回饋時不重算 / 不 `invalidate`；辨識層節流後再餵新 `route`。
- 懸浮窗更新頻率跟隨抓幀節奏，不要每幀重跑幾何。

### 3.4 視覺一致性
- 維持細白實線 + 黑外描邊雙層；白內芯 `2.2dp`、黑外框 `4.2dp`；`Cap/Join ROUND`。
- 不起點大圓、不中段小箭頭、不畫步號；僅起點白圓點、終點白箭頭。
- 若實機出現「直線被誤併」或「交叉仍黏在一起」，先回報是哪個 row/col 區塊，再調圓角半徑與車道槽距，不要回退到複線 / 灰管道方案。
